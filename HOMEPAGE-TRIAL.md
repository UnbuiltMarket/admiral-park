# Admiral Park homepage motion trial

Paste the entire generated `src/framer/AdmiralHomepageTrial.tsx` into the existing Framer hero code file. Keeping that code file retains the existing component instance and the named `OpeningContent`, `BuildingContent`, and `ArrivalCTA` overrides. The trial exports those same names. A new Code Component file is also supported, but native wrappers must then use overrides from that same new file.

Use one component filling one Relative Frame with height 100vh. The navbar stays above it as native Framer content. No sticky spacer or page content below the viewer is needed. Keep GitHub assets enabled, save, and test in Preview. Publish in Framer after accepting the trial. The editor canvas is a static still; interaction runs in Preview and on the published page.

For the quickest check, choose **Start trial: Orbit directly**. For the connected experience, choose **Full journey**. Editor view selects only the still used while editing.

The full journey uses the existing 65-image approach with 0.8-second opening and final fades. A fresh downward gesture after the building appears, or Explore building, enters the orbit. There is no connecting camera sequence in the provided folder, so this trial uses an ordinary 0.35-second handoff dissolve; the lower image stays opaque to avoid a dark dip. Repeated input from the approach's last gesture does not accidentally enter the orbit.

The orbit uses all 120 original 1920x1010 AVIF files from `assets/ORBIT PICKER/BEAUTY sequence_Desktop`. Total encoded size: 4,026,270 bytes (4.03 MB). They are downloaded and decoded with at most four fetches and two motion decodes at once. The default movement decode is 960px wide on desktop and 640px on phones. This reduces working memory; it does not reduce the 4.03 MB download. No source images are resampled or recompressed on disk. A separate phone control prevents an old hero component's 1280px setting from silently carrying into the orbit cache.

All 120 motion bitmaps remain prepared while the viewer is visible: approximately 233 MB of RGBA pixels on desktop, approximately 104 MB on phones, plus browser overhead. A single parked view is decoded again at up to 1920px wide on desktop or 1280px on phones and revealed over 0.12 seconds. Intermediate moving frames are not blended. Destroying the approach on orbit entry frees its decoded frames. Hidden Framer breakpoint instances do not prepare duplicate orbit sets; hiding a previously active instance releases its bitmaps.

Wheel input and horizontal dragging can pass through every checkpoint and make multiple full revolutions. Opposite input reverses immediately. On release, the camera settles to the next checkpoint in the last input direction. Checkpoints default to frames 0,15,30,45,60,75,90,105. Previous/Next view, numbered view buttons, Pause rotation, and Overview are trial controls. Overview returns to the opening panorama; upward orbit input rotates backward rather than leaving the orbit.

The `Wheel speed`, `Drag speed`, `Orbit coast`, `Settle time`, `Orbit decode`, `Phone decode`, `Stopped detail`, and `Viewpoints` controls allow tuning in Framer. Diagnostics show loading and frame counts. Input is routed by the visible viewer's bounds, so full-size transparent Framer wrappers above the component do not swallow wheel or drag input. Covered trial buttons receive their click/tap through the same wrapper, without moving or restyling native Framer layers. Single-finger horizontal and vertical gestures rotate while the orbit is active; two-finger pinch gestures retain browser handling. This routing prevents scrolling past the viewer even if an older tall page section remains. Native navigation, form fields and genuine nested scroll panels retain their behavior; the page's own scrollbar is not treated as a nested panel. Mark other interactive overlays with `data-orbit-ignore` if needed. Arrow keys change viewpoints when the visible orbit is active, including when the page body has focus. Escape pauses. Reduced-motion visitors use viewpoint jumps rather than animated camera travel. Hiding the tab pauses movement. All capture listeners are removed when the viewer unmounts.

To connect a future native navbar Overview control, dispatch `new Event("admiral:overview")` on `window` from its click handler. This page-scoped event only acts on visible instances. The existing navbar's ordinary links need no code changes.

This trial includes camera movement and viewpoint controls. Apartment masks, illuminated hover images, apartment JSON and floorplans have not been provided and are not simulated. It uses the original full-size orbit files; lower-resolution network variants and the connecting sequence can be added after evaluating the motion.

Run `node scripts/build.mjs` after editing the core or wrapper templates. It generates the complete standalone Framer component, including actual asset filenames and content versions. Run `node --test tests/homepage-trial.test.mjs tests/sequence.test.mjs` and `node tests/homepage-trial-browser-check.mjs` for type, SSR, asset and browser checks. `HOMEPAGE_TEST_FILTER` selects browser cases. `HOMEPAGE_PUBLIC=1 HOMEPAGE_TEST_FILTER=public` exercises the real published GitHub assets. The browser checks use real AVIF files, React 18 StrictMode and a Framer API stand-in with the real SDK checked separately; mobile input is Chrome touch emulation. Actual Framer Preview and physical iPhone/Android testing remain the integration checks.
